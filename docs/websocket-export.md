# WebSocket Export — как вытащить все файлы проекта из редактора

Протокол подтверждён по HAR-дампу. Транспорт: **socket.io v4** (`/socket.io/?EIO=4`),
фреймы событий — `42["event", {...}]`. Аутентификация — сессионная кука
(отдельных auth-фреймов в дампе нет).

## Протокол: 2 пары событий

### 1. `read-folder-project` → `folder-contents-project` — дерево проекта

Запрос **без аргументов**: `42["read-folder-project"]`.

Ответ — полное дерево проекта одним фреймом (пагинации нет), массив нод:

```json
[
  {
    "name": "systems",
    "size": null,
    "isDirectory": true,
    "contents": [
      { "name": "spawner.json", "size": 6959, "isDirectory": false }
    ],
    "protected": true
  }
]
```

- `isDirectory: true` → спускаться в `contents` (может быть `[]`).
- `isDirectory: false` → файл; `size` — размер в байтах.
- `protected` — системный файл/папка редактора, на экспорт не влияет.
- У директорий `size: null`.
- Редактор дёргает этот запрос при каждом раскрытии папки — ответ всегда
  дерево целиком (в дампе несколько одинаковых ответов).

### 2. `read-file-project` → `file-contents-project` — содержимое файла

Запрос: `42["read-file-project", {"folderName": "systems", "fileName": "spawner.json"}]`.

- `folderName` — путь папки через `/` (`"maps"`, `"build/maps"`);
  для файлов в корне — **`"."`** (подтверждено: `game.json` читается как
  `{"folderName": ".", "fileName": "game.json"}`).

Ответ — один аргумент:

```json
{
  "folderName": "systems",
  "fileName": "spawner.json",
  "content": "<строка с содержимым файла>",
  "version": "7699cfb181aaf6f2d51f86de3c5f870bebbaad84"
}
```

- `content` — файл целиком строкой (для `.json` — JSON.stringify с отступами;
  парсить `JSON.parse(content)`).
- `version` — **sha1 от байтов `content` (utf8)**, проверено на дампах.
  Использовать для кэша: sha1 локальной копии совпал — файл не качать.

## Алгоритм полного экспорта

1. Подключиться к socket.io (с куками браузерной сессии).
2. Отправить `read-folder-project` → получить дерево.
3. `walkTree`: собрать список `{folderName, fileName}` из листьев
   (`folderName` = путь родителя; корень → `"."`).
4. Для каждого листа — `read-file-project` с этой парой (параллелить можно,
   ответы сопоставлять по `folderName`/`fileName`).
5. `content` → сохранить в `<folderName>/<fileName>` (корень — без папки);
   сверить `sha1(content) === version`.
6. «Обход страниц» из UI — это просто триггер этих же запросов; скрипту
   UI не нужен, достаточно дерева.

## Структура проекта (по дереву из дампа)

| Путь | Назначение |
| ---- | ---------- |
| `game.json` | главный граф (см. `docs/game-graph.md`) |
| `systems/*.json` | графы систем (тики) |
| `modules/*.json` | графы модулей (методы) |
| `components/*.json` | кастомные компоненты |
| `objects/`, `img/`, `audio/`, `assets/` | сущности и ассеты (`assets/*.json` — реестры) |
| `maps/*.json` | тайлмапы (см. `docs/tilemap.md`) |
| `ui/*.json` | UI-сцены (см. `docs/ui-scene.md`) |
| `configs/*.js` | конфиги движка |
| `build/**` | собранная копия (дублирует `maps/`, `ui/` + `game*.js`, `index.html`) — при экспорте можно пропускать |

## Привязка проекта (project id)

**uuid проекта по WS не передаётся вообще** — проверено на HAR-дампах
(ни одного uuid во фреймах). Auth — сессионная кука на handshake.
Привязка происходит на сервере в момент соединения:

1. `GET /project/<uuid>` отдаёт страницу редактора (сервер может запомнить
   «текущий проект» в сессии здесь);
2. ~секундой позже inline-скрипт страницы создаёт сокет — у polling-handshake
   стоит `Referer: /project/<uuid>`, второй зацеп для сервера.

Страница редактора создаёт глобальный подключенный сокет
(`window.socket`, менеджер в `window.__ioManager`) — экспортер может
пользоваться им напрямую.

Следствие для экспортера: **никакой id передавать не нужно** — достаточно
выполняться в контексте открытой страницы `/project/<uuid>` (userscript).
Чужой проект по uuid так не вытащить — нужна сессия с правами и открытая
страница проекта.

uuid проекта виден в URL редактора `/project/<uuid>` и в `data-project`
на публичной странице игры `/game/<slug>`.

## Открытые вопросы

- Бинарные ассеты (картинки в `img/`, звуки в `audio/`): base64 в `content`
  или отдельное событие/HTTP — в дампе папки пустые, не проверено
- События записи (`write-file-project`?) — для двусторонней синхронизации
- Что будет при двух открытых проектах в двух вкладках (одна сессия,
  два сокета) — как сервер различает «текущий проект»
